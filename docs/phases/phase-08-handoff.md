# Phase 08 Handoff — Attendance Management

## Status

Implemented on `phase-08-attendance-management`.

## Delivered

- Server-authoritative check-in, break start/end, and check-out lifecycle.
- Explicit `WORKING`, `ON_BREAK`, and `COMPLETED` state transitions.
- Attendance event history with server receipt timestamps and optional client timestamps.
- Database-backed idempotency for online retries and client event IDs for offline synchronization.
- Persistent mobile offline event queue using SecureStore.
- Attendance history and current-session endpoints.
- Employee correction requests and supervisor/administrator approval or rejection.
- Transactional correction application and append-only attendance audit records.
- Admin attendance dashboard with summary cards, filters, records, and correction review.
- Mobile attendance status, actions, history, offline queue indicator, and synchronization.
- OpenAPI documentation and validation tests.

## API

- `POST /api/v1/attendance/check-in`
- `POST /api/v1/attendance/break/start`
- `POST /api/v1/attendance/break/end`
- `POST /api/v1/attendance/check-out`
- `GET /api/v1/attendance/current`
- `GET /api/v1/attendance/history`
- `POST /api/v1/attendance/sync`
- `POST /api/v1/attendance/:attendanceId/corrections`
- `GET /api/v1/attendance/corrections/mine`
- `GET /api/v1/admin/attendance`
- `GET /api/v1/admin/attendance/summary`
- `GET /api/v1/admin/attendance/corrections`
- `POST /api/v1/admin/attendance/corrections/:correctionId/approve`
- `POST /api/v1/admin/attendance/corrections/:correctionId/reject`

Online timestamps are generated by the API. Offline events preserve their
client-reported timestamp and remain pending until the server processes them.
Rejected or out-of-sequence events remain visible in the synchronization result
and are retained in the mobile queue for explicit handling.

## Migration

`20261102022239_add_attendance_management`

The migration adds attendance sessions, break intervals, event history,
correction requests, and audit records without modifying existing migrations.

## Limitations

Attendance dates currently use UTC because organizations do not yet have a
configured time-zone field. GPS is optional and is not required for attendance.
Break corrections are not exposed yet; correction requests currently support
check-in and check-out timestamps.
